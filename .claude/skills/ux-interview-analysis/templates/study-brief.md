# Study brief – <STUDY ID>

One per study. Lives in the study's Drive folder (private), never in this repo. The agent drafts it
from the research-phase materials; the researcher corrects it. Every run reads it first: it decides
what the reports contain. Write it in the documentation language.

## 1. Study
- ID, client, product, dates, documentation language (or "auto" = doc_language.py rule).
- Participants: pseudonym → interview folder. Excluded sessions (pilot …) and why.

## 2. Goals and research questions
- Each goal: what we answer, which session blocks feed it.
- Hypotheses (IDs, e.g. W1–W5) if the research phase has them.

## 3. Reporting principles
- How findings are worded (e.g. never softened; quote + timestamp + participant count).
- Finding categories (e.g. Bug / UX problem / Request) and where bugs go.
- What counts as a positive finding.

## 4. Client surfaces (coverage)
- Every surface of the client that can appear on screen (site domains, app domains, docs, prototypes).
- Rule: every second a client surface is on screen must be covered by a report block.

## 5. Session blocks
For each block, in planned order:
- name · type (one of: intro, background, persona, first_impression, onboarding, task, free_exploration,
  rating, closing, other) · planned time
- how to recognise it in the recording (moderator cue, link sent in chat, screen)
- what to extract (for its section type) and which metrics apply
- linked resources (persona board, GOMS model/board, task scenario)

## 6. Metrics
- Metric · how it is measured · which block · whether it was actually collected (fill per interview).

## 7. Resources
- Recordings / interview folders, chat transcripts, boards (personas, GOMS, ratings), test data,
  scenario docs, observer notes, earlier studies.

## 8. Deliverables and layout
- Per interview: transcript, session summary, board sections (order).
- Per study: cross-participant synthesis, debrief items, bug log.

## 9. Open items
- Missing materials, deviations from the plan, decisions pending.
